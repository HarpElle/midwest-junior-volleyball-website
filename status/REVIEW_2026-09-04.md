# Midwest Junior Volleyball site: review 2026-09-04

Reviewer: Claude Code (Fable 5.1 review). Read-only; local build, typecheck, and lint were run.

## Executive summary

1. A six-page static Next.js 15 marketing site for Midwest Junior Volleyball and its ASICS Junior National Championships at Navy Pier, built May 2025 and deployed by GitHub Actions to GitHub Pages at `https://harpelle.com/midwest-junior-volleyball-website/`.
2. The build is healthy: `next build` succeeds in about 10 seconds, TypeScript is clean, CI pins every action by SHA with scoped permissions, main is PR-only, and no stale branches exist.
3. The content is a year old: every date, parking link, ticket link, hotel block, and "2025" badge still describes the June 2025 event, and the site's own domain (`midwestjuniorvolleyball.com`) does not resolve.
4. Two dev-only Dependabot alerts are open (browserslist high, @humanfs/node medium), `npm ci` fails on npm 11 because the lockfile is missing optional platform bindings, and `next lint` reports 31 errors that `ignoreDuringBuilds` hides.
5. Most important next step: decide with the client whether this site continues at all. If yes, refresh the event content and clear the two alerts; if no, retire the Pages deployment so a stale tournament page stops being served under harpelle.com.

## Issues

### P0

- None. Nothing is broken for visitors and nothing exposes secrets or private data.

### P1

- **Stale event content served live.** `src/app/page.tsx`, `src/app/schedule/page.tsx`, `src/app/sponsors/page.tsx`, `src/components/layout/footer.tsx` all hardcode June 2025 dates, SpotHero links with `starts=2025-06-...`, a Passkey hotel block, Sportwrench ticket links, and "30th Anniversary Partner - 2025". Fix: move event facts into `src/lib/constants.ts` (`TOURNAMENT_INFO`) and render from there, then update once for the next event.
- **Open Dependabot alerts (dev-only).** `package-lock.json`: browserslist 4.25.0 (GHSA-73wf-gq98-2v4g, high, fixed in 4.28.7) and @humanfs/node 0.16.6 (GHSA-p498-v437-472g, medium, fixed in 0.16.8). Neither ships to the browser. Fix: `npm update browserslist @humanfs/node`, commit the lock, confirm `npm audit` is clean.
- **Lockfile out of sync for npm 11.** `npm ci` fails locally with "Missing: @unrs/resolver-binding-*@1.7.8 from lock file". CI on Node 22 / npm 10 still passes, so the failure is only on newer npm. Fix: `npm install --package-lock-only` on the same commit as the alert bump and commit the regenerated lock.
- **Newsletter forms submit nowhere.** `src/components/layout/footer.tsx` lines 97-108 and `src/app/contact/page.tsx` lines 303-313 are `<form>` elements with no `action` or handler; submitting does a GET back to the same page with `?email=` in the URL. Fix: either replace with the existing `mailto:` newsletter link used on the home page, or wire to a real list provider.

### P2

- **Duplicate Next config.** `next.config.js` (real) and `next.config.ts` (empty template) both exist; Next loads `.js` and ignores `.ts`. Fix: delete `next.config.ts`.
- **basePath duplicated three times.** `next.config.js`, `src/lib/utils.ts#getImagePath`, `src/app/layout.tsx#getAssetPath`. Fix: export the base path from one module and import it in the other two.
- **Lint failing but hidden.** `next lint` reports 31 `react/no-unescaped-entities` errors across `src/app/{page,about,privacy,schedule,terms}.tsx` plus four unused-variable warnings in `footer.tsx`; `next.config.js` sets `eslint.ignoreDuringBuilds: true`. Fix: escape the quotes, remove the unused imports, then drop `ignoreDuringBuilds` and add `npm run lint` to the CI build job.
- **Dead constants.** `src/lib/constants.ts` has `SPONSORS` pointing at PNGs that do not exist, a `(555) 123-4567` placeholder phone, `NAVIGATION_ITEMS` that disagree with `header.tsx`, and `SITE_CONFIG.url` set to a domain that does not resolve. Nothing imports most of it. Fix: either make pages read from it (preferred) or delete the unused exports.
- **Original source images shipped.** `public/images/*/orig/` (about 700 KB of JPG/PNG) is copied into `out/` and deployed even though every page uses the `optimized-*.webp` versions. Fix: move `orig/` folders out of `public/` (for example to `assets-src/`).
- **Unused dependencies.** `framer-motion`, `next-seo`, `react-hook-form`, `@headlessui/react` are in `package.json` but never imported. Fix: `npm uninstall` them; smaller Dependabot surface.
- **Minor markup.** `footer.tsx` wraps a `<Link>` inside `<Button>` without `asChild` (nested interactive elements); `header.tsx` hardcodes `aria-expanded="false"`; footer copyright is hardcoded to 2025 while `currentYear` is computed and unused. Fix: add `asChild`, bind `aria-expanded={mobileMenuOpen}`, use `currentYear`.
- **README is create-next-app boilerplate.** `README.md` says nothing about the site, the Pages base path, or who the client is. Fix: replace with a short project README (purpose, deploy target, how to update event content).
- **Pages HTTPS not enforced.** GitHub reports `https_enforced: false` for this repo's Pages site (the custom domain is inherited from the org site). Low impact since HTTP currently returns 200 rather than redirecting. Fix: enable "Enforce HTTPS" on the org Pages settings.

## Suggestions (value over effort)

1. **Event-config refactor** (M): one `TOURNAMENT_INFO` object drives dates, badges, links, and copyright; annual updates become a single-file change.
2. **Retire-or-continue decision** (S): if the client is not renewing, add a "2025 event has concluded" notice or unpublish; a year-old tournament page under the HarpElle domain reflects on the studio.
3. **Custom domain** (S): if continuing, point `midwestjuniorvolleyball.com` (or whatever the client owns) at Pages via CNAME and drop the `basePath` so links are clean. Unverified whether the client owns that domain.
4. **Add `npm run lint` and `tsc --noEmit` to the PR job** (S): CI already builds PRs; adding lint makes the gate real.
5. **Dependabot config** (S): add `.github/dependabot.yml` with monthly npm and GitHub Actions groups so alerts arrive as PRs instead of drafts.
